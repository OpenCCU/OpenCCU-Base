# AGENTS.md – OpenCCU-Base

Guidance for AI coding agents working in this repository. Human contributors
should start with [README.md](README.md).

## Project overview

OpenCCU-Base holds the source code and prebuilt artifacts of the eQ-3 CCU
components that [OpenCCU](https://github.com/OpenCCU/OpenCCU) builds into its
images: the BidCoS-RF daemon `rfd`, the BidCoS-Wired daemon `hs485d`, their
libraries (`libXmlRpc`, `libelvutils`, `libhsscomm`, `libUnifiedLanComm`, …),
`multimacd`, the Tcl modules, the WebUI, device types and firmware. The
closed-source components (ReGaHss, the HmIP server) are shipped as binaries
only; `src/ReGaHss/` and `src/hmipserver/` contain just a `README.md` and
their changelog.

OS-level changes (Buildroot, kernel, init scripts such as `S61rfd`, packages)
belong in [OpenCCU/OpenCCU](https://github.com/OpenCCU/OpenCCU), which picks up
this repository through its `openccu-base` package.

## Build and test

```bash
cmake --preset x86_64-linux-gnu -DDEPLOY_TO_REPO=OFF   # configure (also aarch64-linux-gnu, arm-linux-gnueabihf, i686-linux-gnu)
cmake --build --preset x86_64-linux-gnu --target rfd   # build one target (rfd, hs485d, XmlRpc, elvutils, …)
make build-x86_64-linux-gnu                             # configure + build everything for one platform
python3 tests/test-components.py                       # build/install selection tests
node --test tests/webui/test-proofandsetvalue.js       # WebUI ProofAndSetValue() tests
node --test tests/webui/test-rega-escapestring.js      # WebUI ReGa.escapeString() tests
node --test tests/webui/test-translate.js               # WebUI translateString() tests
```

Always pass `-DDEPLOY_TO_REPO=OFF` (or use the `Makefile`), otherwise the build
copies its output into `bin/`, `lib/`, … of the working tree.

CI (`.github/workflows/ci.yml`) builds all four platforms in Debian bookworm.
A green CI run proves that the code compiles, not that it works: the daemons
need a radio module or LAN gateway to run. Test behaviour with a small harness
against the real sources (ASan/UBSan/TSan where it fits) and report honestly
what you could and could not test.

## Hard rules

- **Keep line endings and encodings.** Many sources use CRLF, many are
  Latin-1 (ISO-8859-1), some files mix both. Edit them byte-preserving (e.g. a
  small Python script working on bytes) and check `git diff` for stray `^M`
  changes or re-encoded umlauts. Never convert a whole file.
- **Do not hand-edit generated or prebuilt files.** `www/webui/webui.js` is
  generated from `src/webui/www_source/` (`create_webui_js.tcl`,
  `utf82ansi.py`). The prebuilt `libXmlRpc`/`libxmlparser` in `lib/` are
  regenerated by `.github/workflows/update-prebuilt-libraries.yml` after a merge.
  Never commit `build/`.
- **Component versions:** every program and library under `src/` has a
  version, kept in `version.sh` (the daemons, `hss_led`, `ssdpd`, `eq3configd`,
  `eq3configcmd`, `crypttool`, `SetInterfaceClock`, `hs485dLoader`,
  `libhsscomm`, `libelvutils`, `libLanDeviceUtils`, `libUnifiedLanComm`,
  `libeq3config`), in `MODULE_VERSION` (`eq3_char_loop`, `bcm2835_raw_uart`),
  in the Tcl package version (`tclrega`, `tclrpc`, `tcl_homematic`) or in the
  library's version header (`XMLRPC_VERSION_NUMBER` in `xmlrpc_version.h` of
  `libXmlRpc`, `XMLPARSER_VERSION_NUMBER` in `xmlparser_version.h` of
  `libxmlparser`, kept equal to `@version` in `xmlParser.h`).
  A user-visible change raises it (a fix the patch level, a new function the
  minor version), either in the same pull request or in a collected bump.
  CMake generates the header from `version.sh` with `openccu_version_header()`;
  only `rfd` and `hs485d` keep a committed
  `src/<daemon>/generated-<daemon>-version.h`, which is bumped together with
  `version.sh`. Never give the shared libraries a CMake `VERSION` or
  `SOVERSION`: their SONAME must stay the plain `lib<name>.so`, which ReGaHss
  and the OpenCCU packaging load. Each library returns its version from
  `<lib>_version()` (declared in `<lib>_version.h`); a program's `--version`
  (and `-v` where the option is free) prints its own version and the versions
  of the OpenCCU-Base libraries whose functions it calls, read from the loaded
  libraries (check with `nm -D --undefined-only`, not only the link line).
  A program links only the OpenCCU-Base libraries whose functions it calls.
- **Component changelogs:** every component under `src/` has a
  `CHANGELOG.md`. The one of the closed-source `ReGaHss` (`ChangeLog` up to
  R1.00.0388.0267) comes with its binaries from the Release workflow of the
  ReGaHss repository and is not edited here. A pull request with a
  user-visible change adds an entry under `## Unreleased` (create the heading
  at the top if it is missing) to the changelog of every component it
  changes, in the style of the existing entries: what was wrong or what is
  new, written for users, with links to the pull request and the fixed
  issue, and the GitHub user names of its human authors at the end of that
  parenthesis (`([#1](…), fixes [#2](…), @a, @b)`; `(@a)` for an entry
  without links): the author of the pull request and the human co-authors
  of its commits. Never name bots, AI
  agents or language models (e.g. `Copilot`, `github-actions[bot]`); for a
  pull request opened by one, name the human who requested it. A change of
  a library goes into the library's changelog, not into those of the
  programs using it. A version bump renames `## Unreleased` to
  `## <version> (<date>)`; for `webui`, `devicetypes` and `hmipserver`, which
  have no version of their own, the OpenCCU-Base release takes its place.
  The release workflow (`.github/workflows/release.yml`) builds the release
  notes from these changelogs with `scripts/changelog-sections.py`, so keep
  the `## <version> (<YYYY-MM-DD>)` / `## Unreleased` headings and `* ` list
  entries.
- WebUI, Tcl and ReGa code must escape every user-controlled value.
- Changes to the closed-source binaries come from eQ-3; do not patch them.

## Commits, pull requests and comments

- The author of every commit is the human who requested or made the change
  (their name and e-mail address in `user.name`/`user.email`), never a tool or
  an AI assistant.
- Commit messages, pull request titles and descriptions, issue and pull request
  comments and review replies must not mention or credit AI tools or language
  models: no `Co-Authored-By` trailers for tools, no "generated with/by" lines
  or footers, no links to agent sessions.
- Write in English. Subjects follow this repository's style: the affected
  component(s), a colon and a lowercase imperative description, e.g.
  `rfd: …`, `libelvutils, hs485d: …`, `webui: …`. Reference the issue
  (`Fixes #123`).
- One logical change per pull request. Pull requests are squash-merged.
- Fixes for issues found by external test suites name the issue and describe
  how the fix was verified (harness, sanitizer, before/after numbers).
